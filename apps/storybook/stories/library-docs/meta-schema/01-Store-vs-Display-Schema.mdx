# Store schema vs display schema

P1 entity metadata requires two schema layers in apps that stamp `$meta`:

| Layer | Artifact | Used for |
|-------|----------|----------|
| Domain | `itemJsonSchema` | Forms, write validation, `storeSchema` on `LocalOxigraphStoreProvider` |
| Read / UI | `deriveExtendedSchema(domain, profile, { graftPropertyKey: "$meta" })` | `AdbProvider.schema`, detail views, table column scopes |

## Persistence vs JSON keys

- **RDF / SPARQL:** `entityMeta` predicate and variables such as `?entityMeta_modified_single`
- **Loaded JSON:** `$meta.created`, `$meta.modified` (via `remapEntityMetaFromPersistence`)

UI scopes use `$meta`; SPARQL SELECT column ids use the persistence alias utilities in
`@graviola/meta-schema`.

## Demand-driven flat SELECT projection

`SemanticTable` (SPARQL `sparql-select` row shape) passes `annotationScopes` on list
queries. Scopes are derived from visible meta columns, active sort, and `defaultSort`
in `TableUiSchema` — toggling **Created** or **Modified** in the column picker changes
the query and refetches.

- **Default list:** no `entityMeta_*` vars in SELECT (lean queries).
- **Opt-in:** store merges a separate annotation projection channel
  (`annotationProjectionsToSparql`) — domain walk excludes `entityMeta` to avoid
  container columns like `$meta_entity`.
- **Collision rule:** domain `created` → `created_single`; meta `created` →
  `entityMeta_created_single`.
- **Seed data:** entities without a save after meta stamping have no `entityMeta`
  triples; meta cells stay empty until the first stamped write.

## Provider wiring

```tsx
<LocalOxigraphStoreProvider
  storeSchema={domainSchema}
  metaStamping={metaStampingConfig}
>
```

Pass the extended schema only to `AdbProvider` — never as the store root when
`makeStubSchema` is active.

## Regression

`apps/datastore-tests` meta suite includes a **pre-grafted store root** case that
documents the failure mode when this contract is violated.
